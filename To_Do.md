# TerrierPlan — To-Do

Built from `TERRIERPLAN_HANDOFF.md` plus a direct scan of the codebase for `TODO`/`FIXME`/`XXX`/`HACK` markers and every `console.error`/`console.warn` call (2026-08-07). There are zero `TODO`/`FIXME` comments anywhere in the repo — every "confirmed bug" below is instead evidence from actual code behavior (self-admitted incomplete features, dead code paths, version mismatches), not code comments. Every `console.error` call was checked individually; all of them turned out to be normal defensive try/catch logging (failed sign-in, failed course load, failed Firestore write, etc.) rather than evidence of a specific broken path, so none are listed as bugs on their own.

---

## 1. Confirmed bugs

Each of these has direct evidence in the code, not just a suspicion.

- [ ] **Dark mode is genuinely half-implemented** (matches its own commit message, "half implemented dark mode....."). `src/pages/planner.css` has only 8 `data-theme='dark'` override rules in the whole file. Specifically broken: `.external-credit-row.needs-review` and `.import-incomplete-warning` use a hardcoded `#fff5f4` pink background with `#5c1f1c` / `#8a4a45` / `#b42318` / `#176b3a` text — none of these are theme variables, so they won't invert and will look wrong/illegible against the dark palette.
- [ ] **IB external credit is a dead code path.** `type: 'ib'` is fully modeled — `src/utils/externalCredits.js`'s `TEST_TYPES`, `src/data/apIbHubCredit.js`'s `getIbHub`/`IB_HUB_CREDIT`, every `credit.type === 'ib'` check in `HubSidebar.jsx` and `ExternalCreditsPanel.jsx` — but nothing in the codebase ever assigns it. `src/utils/transcriptParser.js` has no `INTERNATIONAL BACCALAUREATE` section detection at all (only `TEST CREDIT`/`ADVANCED PLACEMENT`), and `src/utils/transcriptMapping.js`'s `applyImport` hardcodes `type: 'ap'` for every test-credit row it builds. Real IB credit on an imported transcript will either fail to parse or get mislabeled as AP.
- [ ] **Debug logging is unconditionally on in production**, not gated behind `import.meta.env.DEV` or any flag a user can disable: `DEBUG_IMPORT = true` in `src/pages/PlannerPage.jsx`, `src/components/planner/ImportTranscriptModal.jsx`, and `src/utils/transcriptMapping.js`; `DEBUG_TRANSCRIPT = true` in `src/utils/transcriptParser.js`; `DEBUG_EXTERNAL_CREDITS = true` in `src/components/planner/ExternalCreditsPanel.jsx`. Worse, `TransferExternalCreditRow`'s render and `onChange` handler inside `ExternalCreditsPanel.jsx` call `console.log` with **no flag check at all** — it fires on every render and every keystroke unconditionally. Should all be removed or gated before this matters for perf/noise reasons.
- [ ] **The "mascot" images are not a Terrier.** `public/favicondark.png`, `faviconlight.png`, and `faviconred.png` — used as the login-page mascot, loading spinner, search empty-state icon, and header logo — are generic stock clip-art of a checkmark overlapping two paw prints (confirmed by viewing the actual PNGs), not a dog/terrier illustration, despite `copilot-instructions.md` explicitly asking for "Rhett the Boston Terrier" mascot touches. Minor related contrast issue: the header logo uses `faviconred.png` (a red checkmark) against the scarlet-red header background, so the checkmark stroke nearly disappears (the black paw prints still read fine).

## 2. Not yet built

Per `TERRIERPLAN_HANDOFF.md` and the build order in `.github/copilot-instructions.md` (`1. Planner → 2. HUB Tracker → 3. Scheduler → 4. GPA + transcript/AP/IB import → 5. Degree-requirements engine`). Steps 1–2 are done; step 4 is partially done (transcript/AP/IB import exists, GPA does not have a UI); steps 3 and 5 have not been started at all.

- [ ] **Scheduler page** — section/time picking, conflict detection, live seat availability awareness, blocked-time filters, multiple generated schedule combinations, alternate-section visualization, Google Calendar export, custom class colors, autosave/crash recovery. `users/{uid}/schedules/{scheduleId}` exists in the Firestore schema and rules but is completely unreferenced by any app code — this is a from-scratch build, nothing to extend.
- [ ] **HUB course-finder** ("find me a class that still fulfills my missing HUB unit"). The new HUB-unit filter in `CourseSearch.jsx` is adjacent but not this — it requires the user to already be in the search panel and doesn't cross-reference what's still missing on the HUB sidebar.
- [ ] **GPA UI.** `cumulativeGpa`, `earnedCredits`, and `gradePoints` are scraped from the transcript footer and persisted on the plan doc (`src/pages/PlannerPage.jsx`), but there is no persistent display of them anywhere in the planner — only a one-line summary shown transiently inside the import modal's review step (`ImportTranscriptModal.jsx`, "Transcript totals (saved on plan)" section). A projected/planned GPA calculator for not-yet-taken courses doesn't exist in any form.
- [ ] **Degree-requirements engine** (validating a plan against actual major requirements beyond HUB units — choice groups, credit thresholds, nesting). Explicitly deprioritized in `copilot-instructions.md` ("do not start on this yet") — listed here for completeness, not as something to pick up without being asked.
- [ ] **Manual "add external credit" UI.** There is currently no way to add an AP/IB/transfer credit entry except via a successful transcript import — `ExternalCreditsPanel.jsx` can only edit or remove existing entries, never create new ones.
- [ ] **Custom domain** for Firebase Hosting — still on the default `terrierplan.web.app`, nothing registered.

## 3. Needs manual verification

Implemented in code and looks correct on read-through, but none of this was clicked through live — verify hands-on before trusting it.

- [ ] **Drag-and-drop from a search result directly onto a semester column.** `CourseSearch.jsx`'s result cards are draggable with `data: { from: 'search', courseKey, course }`, and `PlannerPage.jsx`'s `handleDragEnd` checks `active.data.current?.from === 'search'` to route into `handleAddCourse`. The wiring reads correctly, but this specific interaction was flagged as broken in the previous handoff and deserves an actual drag test, not just a code read.
- [ ] **Guest-plan migration to Firestore on sign-in.** `migrateGuestPlanIfNeeded` in `PlannerPage.jsx` has real complexity to it — deduping concurrent calls across React Strict Mode's double-invoke, claiming the localStorage key immediately, restoring it on failure for retry. The logic reads sound, but a full guest → add courses → sign in → confirm everything survived click-through hasn't been done since this was rewritten.
- [ ] **`scripts/patch-fyw-wri.cjs` run status against live Firestore.** This audit had no Firestore access to check. The script is idempotent (`arrayUnion`), so it's always safe to re-run if unsure — but until then, HUB units `FYW` and `WRI` may be unsatisfiable by any course in the tracker. Verify by checking a known course doc (e.g. `CASWR120`) for `hubUnits` containing `"FYW"`.
- [ ] **Dark mode across the rest of the app.** Beyond the two specific hardcoded-color spots already confirmed broken (see Confirmed Bugs), the whole app hasn't been clicked through in dark mode panel-by-panel (search, HUB sidebar, bulletin browser, all three import-modal steps) to find what else doesn't invert correctly.
- [ ] **Transcript PDF parsing accuracy on a real transcript.** `transcriptParser.js`'s column-splitting (left/right by page midpoint) and mode-switching state machine (`terms` / `test` / `transfer`) are logically careful but were never validated against an actual BU unofficial transcript PDF in this audit — only read as code.
- [ ] **Mobile responsive layout on a real device.** Verified in the same session via headless-browser screenshots at various viewport widths, but never confirmed on an actual phone (touch drag-and-drop, on-screen keyboard behavior, real Safari/Chrome mobile quirks).
- [ ] **Email/password Firebase Auth.** The previous handoff claimed it was enabled in the Firebase Console alongside Google Sign-In, but `LoginPage.jsx` only renders a Google button — worth confirming in the Firebase Console whether email/password is still enabled/intended, since nothing in the UI exposes it either way.
- [ ] **Whether `bulletinPages` Firestore collection is truly safe to delete.** Nothing in the current app code reads it (the bulletin browser uses static `bu-programs.js` + a live iframe instead), but confirm nothing else depends on it before deleting.
